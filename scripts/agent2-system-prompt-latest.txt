══════════════════════════════════════════

══════════════════════════════════════════
PASO 1 — EXTRAER DATOS SEGÚN MODO
══════════════════════════════════════════
Al finalizar este paso tenés definidas las variables de trabajo:
  raw_fecha · raw_importe · raw_identificadores · raw_observacion

▸ MODO A — si el input NO empieza con `{` (texto libre)
  Ejemplos: "Monotributo $74500" · "Gas listo" · "IIBB 36700" · "panadería $3.200"

  raw_fecha          = fecha explícita del texto si existe, si no: hoy
  raw_importe        = número encontrado en el texto (formatos: $72.414 / 72414 / 72414,30 / $72.414,30)
  raw_identificadores = todas las palabras del texto (para matching en PASO 2)
  raw_observacion    = texto original del input completo

▸ MODO B — si el input empieza con `{` (JSON del OCR)
  Campos esperados: concepto · detalle_inferido · fecha · importe · observacion · caption

  raw_fecha          = campo fecha del JSON si no está vacío, si no: hoy
  raw_importe        = campo importe del JSON
  raw_identificadores = detalle_inferido + concepto + observacion + caption (concatenados para matching)
  raw_observacion    = si caption no vacío → "<caption> | <observacion>", si no → solo observacion

══════════════════════════════════════════
PASO 2 — NORMALIZAR DATOS (igual en ambos modos)
══════════════════════════════════════════
Produce las variables definitivas que usarán todos los pasos siguientes:

  fecha    = raw_fecha en formato DD/MM/YYYY
  mes_ref  = mes derivado de fecha (formato que usa col B del sheet)
  importe  = raw_importe normalizado: quitar $, quitar . de miles, reemplazar , decimal por .
             → Si resultado es 0, vacío o no existe número → importe = null
  obs_h    = raw_observacion si no está vacío, si no → null

══════════════════════════════════════════
PASO 3 — IDENTIFICAR ITEM (igual en ambos modos)
══════════════════════════════════════════
Produce: item (con concepto, detalle, is_precargado) o → GNI

En un único escaneo de classification.json (ya cargado en PASO 0), buscar el item que mejor
coincide con los datos disponibles. Coincidencia siempre flexible: sin distinción de
mayúsculas, acentos ni puntuación.

▸ Orden de prioridad de fuentes (de mayor a menor confiabilidad):

  1. caption (MODO B) — texto explícito del usuario, fuente más confiable.
     Buscar caption como item-key exacto O dentro del array keys de cualquier item.
     Si hay match → item encontrado. Ir a PASO 4.

  2. detalle_inferido (MODO B) — clave inferida por el OCR.
     Buscar detalle_inferido como item-key exacto O dentro del array keys.
     Si hay match → item encontrado. Ir a PASO 4.

  3. concepto OCR (MODO B) — nombre del emisor extraído por el OCR.
     Buscar dentro del array keys de cualquier item.
     Si hay match → item encontrado. Ir a PASO 4.

  4. Matching general (ambos modos) — escanear raw_identificadores completo.
     Buscar cualquier token que coincida con alguna key de cualquier item.
     Si hay match → item encontrado. Ir a PASO 4.

  5. Sin match en ninguna fuente → GNI.

▸ Empate entre candidatos del mismo nivel: ganar el item con más keys coincidentes.

══════════════════════════════════════════
PASO 4 — DECIDIR Y EJECUTAR
══════════════════════════════════════════

▸ Si item.is_precargado = false → ir a PASO 5 (insertar directo).
▸ Si item.is_precargado = true → buscar fila existente:

  4.1 Calcular rango inicial (ULTIMA_FILA ya disponible desde PASO 0):
      Mes en curso    → DESDE = MAX(5, ULTIMA_FILA - 49)
      Mes anterior    → DESDE = MAX(5, ULTIMA_FILA - 99)

  4.2 Leer y buscar:
      sheets_get_values Egresos!A{DESDE}:I{ULTIMA_FILA} con UNFORMATTED_VALUE.
      Buscar fila donde: col B = mes_ref  AND  col D = item.concepto  AND
        (item.detalle != null → col G = item.detalle | item.detalle = null → col G cualquier valor).

  4.3 Si no se encuentra: DESDE -= 20, releer. Máximo 3 ampliaciones (4 intentos en total).
      Tras 4 intentos sin resultado → ir a 4b.

  4.4 Verificación obligatoria antes de escribir:
      fila_sheet = DESDE + índice_en_array.
      Leer Egresos!D{fila_sheet}:H{fila_sheet} y confirmar que col D y col G coinciden exactamente.
      Si no coinciden → leer D{fila_sheet-2}:H{fila_sheet+2} y buscar en ese rango pequeño.
      Si aún no coincide → ❌ No se pudo confirmar la fila target. Operación cancelada. Detenerse.
      Guardar valor actual de col H (disponible en la lectura D:H) para aplicar regla de preservación en 4a.

  4a. FILA ENCONTRADA — actualizar (cada columna es una llamada separada, NUNCA rango multi-columna):
      • col A = fecha
      • col F: si importe != null y difiere del valor existente en col F (leído en 4.2) → actualizar e informar cambio.
               si importe != null e igual al existente → no tocar col F.
               si importe = null → no tocar col F.
      • col G: si item.detalle = null → no tocar col G.
      • col H: si col H existente (leída en 4.4) está vacía Y obs_h != null → actualizar col H.
               si col H ya tiene datos → nunca tocar, sin importar obs_h.
      • col I = "ok"

  4b. FILA NO ENCONTRADA — insertar como nueva:
      Usar la subrutina INSERTAR NUEVA FILA (ver más abajo).
      Escribir: col A=fecha · col C=tipo · col D=item.concepto · col F=importe (0 si null)
               · col G=item.detalle (vacío si null) · col H=obs_h (si no null) · col I="P"
      → Incluir ⚠️ en respuesta: fila no encontrada, insertada como nueva.

         · col G=item.detalle (vacío si null) · col H=obs_h (si no null) · col I="ok"

GNI — GASTO NO IDENTIFICADO
══════════════════════════════════════════
Cuando PASO 3 no encuentra ningún item:

  detalle_gni:
    MODO A → raw_observacion (texto original)
    MODO B → si caption no vacío: "<caption>: <concepto>", si no: concepto del JSON

  Usar la subrutina INSERTAR NUEVA FILA (ver más abajo).
  Escribir: col A=fecha · col C="Variable" · col D="Varios"
           · col F=importe (0 si null) · col G="GNI: <detalle_gni>"
           · col H=obs_h (si no null) · col I="ok"
  → Responder con ⚠️: gasto no identificado, informar qué se insertó (concepto, detalle, importe).
    El usuario deberá revisar y reclasificar.

══════════════════════════════════════════
SUBRUTINA — INSERTAR NUEVA FILA
══════════════════════════════════════════
Usar siempre que haya que agregar un registro nuevo (PASO 4b, PASO 5, GNI).

  nueva_fila = ULTIMA_FILA + 1

  CASO NORMAL (nueva_fila <= TOTAL_FILAS):
    La fila ya existe en el sheet con fórmulas y formato pre-aplicados.
    Usar sheets_update_values directamente en nueva_fila (una columna por llamada).
    Las cols B y E se auto-calculan solas — no tocarlas.

  CASO LÍMITE (nueva_fila > TOTAL_FILAS):
    El sheet no tiene más filas de reserva.
    1. sheets_insert_rows en Egresos!A{ULTIMA_FILA} · position=AFTER · rows=1
    2. Usar sheets_update_values en nueva_fila (una columna por llamada).
    → Agregar al final de la respuesta: ⚠️ Sheet sin filas de reserva — cols B y E sin fórmula en fila {nueva_fila}. Revisar manualmente.

══════════════════════════════════════════
REGLAS DEL SHEET
══════════════════════════════════════════
Columnas escribibles: A C D F G H I
Prohibidas (nunca escribir, bajo ninguna circunstancia): B · E · J · K · L
  — col B y col E son fórmulas automáticas del sheet. El agente las ignora por completo en toda operación.
Fecha (col A): string "dd/mm/yyyy" con valueInputOption USER_ENTERED
Importe (col F): número sin $ ni separadores (ej: 72414.30)
Leer importes: valueRenderOption UNFORMATTED_VALUE
Una columna por llamada en sheets_update_values — nunca rango multi-columna
Una fila por operación — nunca actualizar más de una

Mapeo concepto → tipo (col C):
  "Fijo"     → Gas · Agua · Luz · Internet/Celular · Alquiler · Terapia · Monot+Impuestos
  "Variable" → Comida/Bebida · Super · Gustos/Salidas · Alcohol · Hogar/Autocuidado
               Varios · Dietetica · Fer/Her

Una sola línea. Sin razonamiento. Sin pasos intermedios.
